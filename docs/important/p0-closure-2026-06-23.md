## 本会话补全：P0-2 RAG 向量管线（唯一未接线项）

前序会话把 `SqliteVectorRetrievalPort`、`RemoteOpenAiCompatibleEmbeddingProvider`、executor 的 `searchPort` 参、ingestion 的 `embeddingProvider` 参全部实现，但**生产零连接**：dispatcher 构造 `ProjectRagRetrievalToolExecutor()` 不传 port、ingestion 两处生产构造 `RagTxtCorpusIngestionService()` 不传 provider、`RemoteOpenAiCompatibleEmbeddingProvider` 全仓零实例化。检索永远走 `_lexicalSearch`，且结果以"已召回语料证据片段 N 条"呈现——即审计主线"关键词回退冒充语义检索"。

### 1. 诚实标注（commit `9d18d2b`）

检索 executor 不再冒充。`_searchHits` 返回 `_SearchOutcome`（hits + mode），mode 取值：
- `vector`：向量端口正常召回。
- `lexical`：未注入/未解析出向量端口，走关键词匹配。
- `lexical_fallback`：注入了端口但本次嵌入/检索抛错，降级到关键词。

`retrievePassages` 透出 `retrieval_mode`；词法模式的 `display_text` 标"（关键词匹配）"，`warning_notes` 加诚实提示（"当前未注入向量检索端口，结果为关键词匹配（非语义检索）。" / "向量检索不可用，已降级为关键词匹配（非语义检索）。" / "已启用向量检索但未召回命中，可能语料尚未生成嵌入。"）。3 个回归测试覆盖三模式。

### 2. 端到端接线（commit `d8eb66e`，按可选配置门控）

- **`SettingsBackedEmbeddingProviderResolver`**（新，adapters）：读默认 provider 凭据（baseUrl/apiKey）+ `AppSettings.extraSettings['embedding_model_id']`，构造 `RemoteOpenAiCompatibleEmbeddingProvider`；未配置 embedding 模型或缺凭据返回 null（调用方诚实降级）。配置放 `extraSettings`，**免改 settings schema/UI**——专用 UI 字段将来写同一键即可。
- **检索**：`ProjectToolDispatcher` 接 async `ragSearchPortResolver`；`adapter_bundle` 从 `settingsRepository` 闭包构造 resolver（每次检索读当前设置）；executor 惰性解析向量端口（`searchPortResolver`，设置可运行时变），失败降级 `lexical_fallback`。
- **入库**：`RagTxtCorpusIngestionService` 接同一惰性 `embeddingProviderResolver`，`_embedChunks` 入库时解析；app 的 `ProjectRagExtractionExecutionService` 从当前 `_settings` 解析并透传，配置齐全时 chunk 落 `embedding_blob`，否则纯元数据。
- **CLI**：rag_command 用空 settings（无 providers）→ 诚实元数据，不触网。

**效果**：用户在默认 provider 配 embedding 模型即获端到端语义 RAG（入库生成向量 + 检索向量召回）；否则全程诚实降级到关键词（已如实标注，不再冒充）。
