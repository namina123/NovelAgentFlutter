# 拆书与拆书项目完整性修复计划

> 日期：2026-07-22
>
> 范围：拆书项目创建、导入、纯分章、可选模型分析、确认进入创作、项目类型复合、派生项目兼容，以及 Markdown/SQLite 两种存储策略。

## 目标合同

流程固定为：**创建/打开具备拆书能力的项目 -> 导入可恢复的源文 -> 纯分章 -> 可选分析 -> 审阅并选择要应用的内容 -> 原子地进入创作**。

必须满足以下不变量：

1. 用户未勾选的条目绝不能被当作已应用内容写入。
2. 不可执行的目标（例如缺运行基准的 `long_novel`）必须在写入前被阻止。
3. 确认失败不能伪装成失败后仍留下不可辨识的半完成项目；至少要有预校验、完成标记和可恢复状态。
4. `book_deconstruction` 是能力，而非只靠 `projectType` 判断的瞬时页面类型；复合为写作项目后仍可重新进入拆书工作流并读取结构化源文。
5. 任何异步操作只属于其启动时的项目，取消或切换项目不得污染另一个项目。
6. 拆书源文和续写正文必须遵守项目存储策略：SQLite 项目同时写入主事实源，Markdown 项目以文件为主。
7. 用户离开、重启或重新打开项目后，至少能恢复源文、拆书结果、选择与确认状态，或明确展示可继续的恢复入口。

## 已确认问题

| 编号 | 问题 | 风险 | 修复方向 |
| --- | --- | --- | --- |
| BD-01 | `selectedItemIds` 只影响预览，确认时仍写入全部章节，且未调用 materializer。 | 用户选择失效、误写入 | 让确认调用 materializer，并把章节持久化也绑定到选中章节。 |
| BD-02 | 确认页可选 `long_novel`，但没有运行基准；写入在类型转换前发生。 | 必现失败、半完成写入 | 引入确认预校验和运行基准选择；所有副作用在可执行计划通过后才开始。 |
| BD-03 | manifest 已保存附加 trait，但运行时 descriptor/入口未消费。 | 复合项目重开后失去拆书能力 | 贯通 descriptor、仓储、capability guard 和入口判断。 |
| BD-04 | 操作代际未绑定项目；取消未覆盖确认/派生。 | 跨项目污染、取消后仍写盘 | 为操作记录项目根和代际，切项目立即失效；确认/派生使用不可取消的提交边界。 |
| BD-05 | 快照和粘贴源文只在内存中。 | 重启/切换后无法恢复 | 持久化工作流状态及可恢复源文引用。 |
| BD-06 | SQLite 路径通过通用文件写入，绕过 `body_text_document`。 | 主事实源与文件投影分叉 | 源文和正文走 `ProjectStructuredContentBridgeService`。 |
| BD-07 | 创建时选承接路线，但当前确认页无路线选择；派生服务无 UI 主入口。 | 业务语义断裂 | 明确采用“同项目复合”作为主线，路线仅保留为可解释的创作偏好；派生流程单独恢复入口或退役。 |
| BD-02a | 复合后的同类型 `long_novel` 可选不同运行基准，但确认不写 manifest/runtime profile。 | journal 与项目实际运行配置分叉、历史预览被误判为已确认 | 同类型确认锁定项目既有基准；服务层在任何写入前拒绝不一致参数，并使旧的假确认预览失效。 |

## 实施顺序

### Phase A - 不可逆写入前的正确性

- [x] BD-01：选中条目控制 materialization 和章节写入。
- [x] BD-02：增加确认计划预校验；`long_novel` 必须选择运行基准。
- [x] BD-02：将确认写入组织为可报告的提交步骤，失败保留明确恢复信息。
- [x] BD-02a：同类型 `long_novel` 只复用项目已保存的运行基准；界面锁定选择，确认服务拒绝不一致输入，恢复时清除历史假确认预览。

验收：取消任一章节后，该章节的章节大纲和正文均不会写入；无基准时确认按钮不可用；类型转换失败不会在无提示下留下半完成结果。

### Phase B - 项目能力与异步边界

- [x] BD-03：把 `additionalTraitIds` 带入 `ProjectDescriptor`，并以 `ProjectCapabilityService` 替换拆书入口的字符串判断。
- [x] BD-04：操作令牌同时包含 generation 和 project root；切换项目、刷新到新项目、取消时使旧令牌失效。
- [x] BD-04：确认开始后冻结界面输入；提交结束后才允许修改。

验收：复合后的项目重开仍自动识别拆书能力；A 项目长操作结束后无法改变 B 项目状态或内容。

### Phase C - 持久化与恢复

- [x] BD-05：定义并持久化拆书工作流快照，恢复源文、分章、选择、分析状态和确认记录。
- [x] BD-06：SQLite 导入原文和正文继承写入主事实源，同时保留投影。

验收：重启后可继续确认，无需重新导入；SQLite `body_text_document` 含 source_original 和 chapter 记录。

### Phase D - 流程收口

- [x] BD-07：确认“同项目复合”是唯一主线，隐藏无效路线选择；不得同时保留无效路线选择。
- [x] 成功确认后进入对应创作工作台，并保留回到拆书审阅的入口。

验收：创建页、拆书页、确认页和项目重开后的文案/行为表达同一条流程。
