# NovelAgent Flutter 迁移顺序文档

最后更新：2026-05-24

## 目标

把旧项目 `D:\GODOTProject\NOVELAgent` 的可用能力持续迁移到当前 Dart / Flutter 项目中，并满足以下长期约束：

- core、adapters、app、ui 职责明确
- 单一职责原则
- 一个文件尽量只承载一个职责类或一个清晰的小职责集合
- GUI 与 CLI 最大复用同一套 core 运行链
- 项目内生态、工具、工作流、长任务、审稿、模板等能力逐步对齐旧项目
- 不把临时宿主实现、硬编码文案、无关内容写死在项目里

## 分层约束

### Core

- 放纯逻辑、规则、用例、合同、渲染器、调度器、规范化器
- 不直接依赖 Flutter、桌面文件选择器、移动端权限或宿主 UI

### Adapters

- 放本地文件系统、项目目录、设置仓储、工具分发、包扫描、平台路径适配
- 为 core 提供稳定端口实现

### App

- 放控制器、页面状态装配、页面间导航、视图数据投影
- 不把复杂算法和文件系统细节堆在控制器里

### UI

- 放页面、面板、子控件、动作接口
- 不直接读写项目文件，不直接处理业务规则

## 当前执行策略

当前采用“先打通真实链路，再做表单化与细节打磨”的策略：

1. 优先消灭假入口和空按钮
2. 优先让每个页面入口都能落到真实用例
3. 优先复用已迁移 core，不在 app 层二次造业务逻辑
4. 每完成一个切片就更新进度文档与验证结果
