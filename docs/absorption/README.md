# 参考项目吸收层

## 目的

这层目录专门用于整理 `references/` 下参考项目中值得被 `NovelAgentFlutter` 吸收的能力、策略、交互理念与架构启发。

这里不做源码转译，不做字段照搬，只做三件事：

1. 提炼可吸收能力
2. 明确落到我们哪一层架构
3. 明确它服务哪些策略、如何与现有设计融合

## 目录设计

```text
docs/absorption/
  00-governance/
  10-projects/
  20-synthesis/
```

### `00-governance`

放吸收工作的统一规则：

- 适用边界
- 术语
- 模板
- 许可证限制
- 架构落点口径

### `10-projects`

按单个参考项目拆分。

每个项目目录后续都按同一模板总结：

- 这个项目真正强在哪里
- 哪些点适合我们吸收
- 应落到 `core / adapters / app / ui` 的哪一层
- 能服务哪些 `project_strategy / mode_strategy / workflow_strategy`
- 与我们现有设计如何融合
- 哪些点必须明确不吸收

### `20-synthesis`

放跨项目汇总，不按来源项目，而按我们自己的产品和架构视角归并：

- 能力总表
- 策略覆盖矩阵
- 架构落点总图
- 吸收优先级与实施回填

## 后续工作方式

后续我们按“一个参考项目一次总结”的节奏推进。

每次总结完成后，至少要回填四类信息：

1. 单项目吸收结论
2. 架构落点
3. 策略适配范围
4. 跨项目归并项
