# 吸收层治理

## 作用

这个目录负责约束“怎么吸收”，避免后续文档变成随手摘抄。

## 这里要统一的内容

- 吸收边界
- 许可证限制
- 架构落点口径
- 策略标签口径
- 单项目总结模板

## 必守边界

### 1. 只吸收理念，不转译实现

对于 GPL 等受限参考项目，只允许吸收：

- 产品理念
- 交互经验
- 能力分层
- 状态建模方向
- 工作流拆分思路

不允许：

- 复制源码
- 转译具体实现
- 原样照搬字段设计
- 原样照搬 prompt 文本

### 2. 所有吸收结论都要回到我们的架构

每个结论都必须能回答：

- 属于 `core / adapters / app / ui` 哪一层
- 对应哪些共享端口、策略或资产
- GUI 和 CLI 中谁复用、谁不复用

### 3. 所有吸收结论都要回到我们的策略模式

每个结论都必须能回答：

- 服务哪些 `project_strategy`
- 服务哪些 `mode_strategy`
- 服务哪些 `workflow_strategy`

### 4. 吸收结果必须可实施

不写纯感想。

每条可吸收内容，后续都应能继续落成：

- 核心资产
- 核心服务
- 适配器
- 页面入口
- 迁移顺序
