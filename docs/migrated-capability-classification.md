# 已迁移能力分类

## 目的

这份文档把当前已经迁移进 Dart 体系、并且后续仍会继续扩展的能力，按下面三类整理：

- 长期任务专属
- 长期任务与一般协作模式可共用
- 特殊建议

这样做的目的不是把能力写死，而是先明确默认归属，避免后面继续把不同层级、不同节奏的能力混在一起。

## 一、长期任务专属

这类能力默认服务于“任务链、检查点、恢复推进、阶段控制”。

### 1. 长任务任务链与调度

- `task_queue`
- `task_runtime`
- `workflow_runtime`
- `scheduler_tick_plan`
- `next_batch_plan`
- `run_center_contract`
- `unattended_strategy`
- `long_task_loop_guard`
- `long_task_batch_option`

说明：

这些能力的核心是“持续推进而不是单轮回答”，天然属于长任务。

### 2. 长任务计划与运行记录

- `long_task_plan_record`
- `long_task_run_record`
- `long_task_run_step_recorder`
- `long_task_scheduler_snapshot`
- `long_task_scheduler_markdown_renderer`
- 长任务链路树 / 回放 / 日志视图

说明：

它们的职责是让运行可恢复、可回看、可诊断，一般协作模式不默认需要这么重。

### 3. 长任务进入策略

- 生成长篇队列
- 运行下一步
- 受控连续运行
- 长任务模式化开局

说明：

这部分是长任务专属入口，不该和普通“问答 / 单轮创作 / 局部修订”入口混在一起。

## 二、长期任务与一般协作模式可共用

这类能力应该尽量放在 core，作为 GUI / CLI 统一复用能力。

### 1. 会话与上下文能力

- `session_record`
- `session_history`
- `session_context_renderer`
- `context_assembler`
- `context_budgeter`
- 压缩策略
- 上下文纳入策略
- 错误不入上下文策略

说明：

无论是普通协作还是长任务，都需要这些会话基础设施。

### 2. 智能体与协作能力

- 智能体目录与组加载
- 技能目录与组加载
- 子智能体调用
- 智能体工具策略
- 智能体模型覆盖
- 协作组和委派简报

说明：

它们不是长任务专属，而是“任何需要多智能体协作的模式”都能共用。

### 3. 工具调用与项目操作

- `list/read/write/edit/move/delete/backup/...`
- `present_user_options`
- `set_agent_tasks`
- `request_gateway_tool`
- `reorder_project_file`
- 工具暴露过滤层
- 工具调用去重
- 流式 `tool_call` 聚合

说明：

这些是共享运行骨架的一部分，普通协作和长任务都依赖它们。

### 4. 生成与修订能力

- `generate_draft`
- `chapter_atomic`
- `revision_diff`
- 长任务里的正文生成
- 普通模式里的草稿生成

说明：

底层生成、局部修订、工具调度和结果落盘本质上是一套共享能力，不该各做一份。

### 5. 项目与生态资产能力

- 项目创建 / 打开 / 检测
- 项目级 `agents / skills / agent_groups / skill_groups`
- 模板读取、编辑、保存
- 生态包导入
- 索引生成
- 角色 / 组织 / 风格等后续资产化方向

说明：

这批能力属于项目级基础设施，天然横跨普通协作与长任务。

## 三、特殊建议

这类能力不是某一种模式独占，但不建议默认无脑开启，需要由项目类型、场景或用户偏好决定。

### 1. 需要显式确认密度的能力

- 自动连续运行
- 自动写入正式正文
- 自动回写长期记忆
- 自动批量修订

建议：

这些能力要由策略控制，不要写死在单一模式里。

### 2. 高结构化写作辅助

- 伏笔管理
- 章节关系图谱
- 分析后一键重写
- 拆书
- 风格资产化
- 职业等级体系

建议：

这批能力应先进入共享 core 模型层，再由不同模式按需启用，不要一开始就和某个具体页面绑死。

### 3. 平台受限能力

- 命令执行
- 某些 gateway 宿主工具
- 桌面路径选择

建议：

它们属于宿主边界，不该进入模型默认可见工具集，更不该和核心写作逻辑耦合。

## 长任务开局模式建议

当前建议保留下面五种长任务写作模式：

### 1. 灵感托管式长篇

- 人类只给灵感、世界观、题材、禁区、结局方向
- 智能体负责全书结构规划和后续推进
- 适合只有种子、希望高自动化的人

### 2. 全书共拟式长篇

- 人类与智能体先讨论完整主线、卷结构、角色弧光
- 确认后再进入长任务执行
- 适合想先把全书走向谈清楚的人

### 3. 分卷检查点式长篇

- 先定总主线
- 以“卷”为阶段推进
- 每卷结束回到人类确认

### 4. 章纲监督式长篇

- 人类主要确认阶段目标和章纲
- 正文、后处理、回写由智能体推进
- 适合希望控节奏但不想逐段盯写的人

### 5. 旧稿抢救重构式长篇

- 从旧稿、碎稿、废案、大纲残片起步
- 先盘点与重构，再恢复正式写作
- 适合已经写乱、写断或换过多版方案的项目

## 当前约束

1. 长任务模式定义应进入 core，不写死在 Flutter 页面
2. UI 只负责展示这些模式和收集选择
3. 真正的进入提示词、任务链生成策略、检查点密度应由共享服务决定
4. 后续若模式调整，只改模式目录与对应策略，不要改散落在多个页面里的文案分支
