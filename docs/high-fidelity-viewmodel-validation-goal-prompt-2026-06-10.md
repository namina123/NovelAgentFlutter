# 高保真 ViewModel 验收目标模式总提示词

最后更新：2026-06-10

把下面整段直接交给目标模式使用：

```text
根据 `docs/high-fidelity-viewmodel-validation-session-order-2026-06-10.md` 启动高保真 ViewModel 验收、修复与重跑主线。

本轮目标是从 GUI ViewModel / Controller / action handler 路径高保真模拟真实用户交互，验证普通项目、长任务、多智能体、信息收集、知识库、网络资料、同人写作、拆书续写、表达限制、watchdog/supervisor、工具动态状态等能力是否真正可用。

硬约束：

1. 从 HFVV-01 开始按顺序执行，不跳 session。
2. 每个 session 完成后确认本 session。
3. 每条主测试线都必须从新项目开始。
4. 不允许用旧探针捷径跳过前置流程，不允许直接预设“生成第 N 章”作为普通项目主验收。
5. 测试必须通过 ViewModel 状态、会话条目、工具状态、资源树、长任务站、项目文件和运行记录共同判定。
6. 每一步都要读取模型真实返回，根据返回动态决定下一步：确认、等待工具、继续提问、启动资料收集、推进大纲、进入写作、触发审核或定位失败。
7. 工具结果可能是耗时返回。pending 工具必须动态显示和等待，不能把空结果当成功，也不能把执行中误判成失败。
8. 每条 lane 独立 workspace、独立 report、独立修复重跑闭环。建议统一放在 `artifacts/high_fidelity_viewmodel_validation/<run_id>/<lane_id>/`。
9. 并行测试线可以同时启动，但任何一条失败都要立即分类、定位、修复并重跑该线，不等所有线全部跑完。
10. 修复必须优先落在生产链路，不能只在 probe / harness 里吞错。
11. 修复后必须补 focused test 或 contract test，并重跑失败 lane 与受影响相邻回归。
12. 题材输入不能写进 core；快穿、哈利波特、Re:Zero、历史科技都只是测试材料。
13. 长任务测试线至少跑到 50 个有效章节；有效章节必须有正文、落盘证据、状态记录和工具事件。50 章是验收口径，不是产品核心硬编码，不能预排章节清单，要让智能体自然规划推进。
14. 表达限制、知识卡、知识库调用、多智能体、watchdog/supervisor、来源安全、SQLite/结构化基底、GUI 动态状态都是横切验收点。
15. 不打印、不提交 API key、私有配置、大体量原文复制或不必要测试产物。来源记录不能把本机绝对路径当作可分发事实源。
16. 保持解耦合、单一职责，避免单文件过重，不造第二套业务 runtime，不把测试 harness 变成新的业务中心。

优先执行：

先执行 HFVV-01。只做基线审计与高保真测试计划冻结：读分析文档、确认并行 lanes、失败分类、产物目录、API/代理/语料存在性，不打印或提交 key，不开始长时间真实测试，不修业务代码，不开启下一任务。
```
