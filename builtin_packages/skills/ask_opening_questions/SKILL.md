# 开局澄清问题

## 使用时机

在以下情况触发：

1. 用户只说“写个开头”“想个故事”“做个设定”。
2. 用户的需求里缺少会显著影响后续创作的关键信息。
3. 当前直接开写会导致风格、题材或主线偏差太大。

## 工作流程

### 第一步：判断是否真的需要追问

先检查现有上下文是否已经足够支撑下一步。如果题材、主角目标、冲突方向和输出形式已经基本明确，就不要为了“显得认真”继续追问。

### 第二步：只问最关键的问题

优先围绕以下缺口提问：

1. 题材与气质
2. 主角或核心视角
3. 目标产物是大纲、设定、样章还是正式正文
4. 是否有必须遵守的风格或禁区

把问题控制在 1 到 3 个，避免把用户拖进长问卷。

### 第三步：在不宜追问时改给方向

如果用户明显不想来回澄清，直接给 2 到 4 个互相区分清楚的方向。每个方向只写最能帮助决策的差异点，不展开成长文。

## 约束

1. 不要问可以从已有上下文直接推出的问题。
2. 不要问过细、过早的问题，例如还没确定题材就追问某个支线角色名字。
3. 不要把澄清问题伪装成已经确定的设定。
4. 没有工具时也应直接输出问题或方向，不把能力缺失变成阻塞。
