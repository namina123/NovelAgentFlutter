# 章节摘要

## 使用时机

在以下场景触发：

1. 单章或单阶段产出完成后，需要保存可复用摘要。
2. 会话过长，需要保留后续续写最关键的信息。
3. 需要给别的流程或智能体提供压缩上下文。

## 工作流程

### 第一步：只提取后续真的要用的信息

优先保留：

1. 发生了什么
2. 谁因此改变了状态或立场
3. 哪些伏笔被埋下或被回收
4. 哪些问题还没解决
5. 哪些风格、语气或关系状态必须延续

### 第二步：区分“事件结果”和“原文细节”

摘要不是正文复写。不要把长对白、细枝末节动作和可从正文轻易重建的描写堆进摘要。

### 第三步：为下一步提供可执行提示

在摘要结尾明确指出后续续写最该注意的 2 到 5 个约束或待推进点。

## 约束

1. 摘要要短，但不能丢掉会影响后续决策的硬事实。
2. 不要把灵感猜测写成已确认事实。
3. 没有工具时直接输出摘要正文；有项目写入能力时再落到摘要目录。
4. 如果当前内容本身含糊，要显式标记“不确定项”，不要假装已经确认。
