# 技能创建参考指南

本参考文档用于补充 `SKILL.md`，只在需要更细节的技能设计说明时按需读取。

## 技能的目标

技能不是“把一个回答保存下来”，而是把反复出现、可复用、对另一个模型真正有帮助的执行知识沉淀成包。

技能常见承载内容：

1. 多步骤工作流程
2. 领域知识与规则
3. 可执行脚本
4. 按需加载的参考文档
5. 最终输出要用的素材或模板

## 设计 checklist

创建技能前先确认：

1. 技能解决的是什么问题。
2. 用户会如何表达这个问题。
3. 哪些步骤会反复出现。
4. 哪些信息是 SKILL.md 必须知道的。
5. 哪些信息更适合下沉到 `references/`。
6. 哪些行为需要脚本而不是重复生成。

## 渐进式披露

遵循三层结构：

1. frontmatter：短描述，负责“是否触发”
2. `SKILL.md` 正文：短流程，负责“如何做”
3. 资源目录：细节、脚本、模板，负责“按需深入”

## 工具解耦

技能正文不要直接假设某个宿主内置工具一定存在。

优先写：

1. 所需能力是什么
2. 能力存在时怎么做
3. 能力缺失时怎么降级

例如：

- 不写“必须调用某某工具”
- 改写为“有文件写能力时创建目录与文件；否则输出完整目录草案和文件内容”

## 何时放脚本

当某个步骤满足以下任一条件时，优先下沉到 `scripts/`：

1. 每次都在重复写同样逻辑
2. 人工很容易漏步骤
3. 结果需要更确定
4. 适合自动化批处理

## 何时放 references

当信息具备以下特点时，优先放到 `references/`：

1. 很长
2. 不是每次都需要
3. 是详细规范、规则、模式、接口说明
4. 会随着时间迭代

## 何时放 assets

当文件不是给模型“读”的，而是给模型“拿来产出”的，就应放到 `assets/`。
