# 连续性检查

## 使用时机

在以下场景触发：

1. 续写前要确认旧稿没有硬冲突。
2. 修订后要检查是否引入新的设定矛盾。
3. 用户要求做剧情、人物、时间线或风格连续性检查。

## 工作流程

### 第一步：明确检查范围

先判断这次重点检查什么：

1. 角色动机与已知信息
2. 世界规则与能力边界
3. 时间线、地点、伤势和物品状态
4. 伏笔、承诺与已回收信息
5. 文风和叙事口径

### 第二步：只报告真正会影响后续创作的问题

优先找：

1. 前后矛盾
2. 逻辑断裂
3. 状态跳变无解释
4. 伏笔丢失或提前泄露

不要把单纯的审美偏好都当成连续性错误。

### 第三步：给出可执行修复建议

每个问题至少说明：

1. 问题是什么
2. 影响在哪
3. 修哪里最省改动

## 约束

1. 区分“明确错误”和“可讨论优化”，不要混写。
2. 没有工具时直接输出问题清单；有报告写入能力时再落成检查报告。
3. 如果证据不足，要写明“疑似冲突”而不是武断下结论。
4. 修复建议优先选择最小改动方案。
